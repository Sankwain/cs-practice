# Воркшоп lab03: история, сравнение, восстановление

## Различия между git diff, git show и git log

- **git diff** — показывает различия между двумя состояниями (рабочая папка vs индекс, или два коммита). Не показывает метаданные коммита (автора, дату, сообщение).
- **git show** — показывает **один конкретный коммит** целиком: метаданные (автор, дата, сообщение) и изменения, которые он внёс. Удобно для просмотра "что именно было в этом коммите".
- **git log** — показывает **историю коммитов** (список). Не показывает сами изменения, только кто, когда и с каким сообщением делал коммит. С флагом --stat добавляет статистику изменений.

## Что нашли git log -S и git blame

- **git log -S"def"** — нашёл все коммиты, в которых изменилось количество вхождений строки "def" в файле. То есть показал моменты, когда добавлялись новые функции.
- **git blame** — для каждой строки файла показал, в каком коммите и кем она была добавлена. Позволяет отследить историю каждой строки.

## git restore vs git restore --source

- **git restore <файл>** — отменяет изменения в рабочей папке, возвращая файл к состоянию **последнего коммита** (или индекса, если файл был добавлен через git add). Все несохранённые правки теряются.
- **git restore --source=HEAD~2 <файл>** — берёт версию файла из **указанного коммита** (в данном случае — два коммита назад) и кладёт её в рабочую папку. Это не коммит, просто замена содержимого файла.

Если бы я не сделал финальный git restore, мои ручные правки (удаление строк) так и остались бы в рабочей папке, и следующий коммит зафиксировал бы их.

## git revert vs git reset --hard

- **git revert HEAD** — создаёт **новый коммит**, который отменяет изменения предыдущего. История остаётся полной и линейной. Безопасно для опубликованных репозиториев, потому что не переписывает историю.
- **git reset --hard HEAD~1** — **стирает** последний коммит из истории и возвращает файлы к состоянию до него. История меняется, и если коммит уже был отправлен на GitHub, это создаст проблемы для других разработчиков.

**Почему revert безопаснее в опубликованной истории:** потому что он не удаляет коммиты, а добавляет новые. Другие люди, которые уже скачали репозиторий, не столкнутся с конфликтами при pull. Reset же "переписывает историю", и при следующем push потребуется force push, что может затереть чужую работу.

## Тег vs ветка

- **Тег** — это постоянное имя для конкретного коммита. Он не двигается: всегда указывает на один и тот же коммит. Используется для маркировки версий (v1.0, v2.0), релизов, важных точек в истории. Через полгода по тегу можно найти ту самую версию.
- **Ветка** — это подвижный указатель, который двигается вперёд с каждым новым коммитом. Ветки используются для активной разработки, экспериментов, фич. После слияния ветку обычно удаляют.

Тег — это "фотография" момента. Ветка — это "текущая линия разработки".
