## Git и GitHub: в чём разница
**Git** — это система контроля версий, программа, которая устанавливается на твой компьютер. Она отслеживает изменения файлов, создаёт коммиты, управляет ветками. Git работает локально.

**GitHub** — это веб-сервис, который хранит Git-репозитории в интернете. Он позволяет делиться кодом с другими, совместно работать над проектами, создавать pull request'ы и Issues. GitHub использует Git под капотом, но добавляет удобный интерфейс и социальные функции.

Проще говоря: Git — это инструмент, GitHub — это платформа для хранения и обмена результатами работы этого инструмента.

## Использованные команды

### git status
Показывает текущее состояние репозитория: какие файлы изменены, какие добавлены в индекс, какие не отслеживаются. Помогает понять, что происходит перед коммитом.

### git diff
Показывает различия между рабочей папкой и индексом. То есть изменения, которые ты сделал, но ещё не добавил через git add.

### git diff --staged
Показывает различия между индексом и последним коммитом. То есть изменения, которые уже добавлены в индекс и готовы к коммиту.

## Ветки

### Что такое ветка
Ветка — это независимая линия разработки. Она указывает на определённый коммит и двигается вперёд вместе с новыми коммитами. Ветки позволяют работать над разными задачами параллельно, не мешая основной линии разработки (main).

### Что происходит при новом коммите
Когда ты делаешь коммит в ветке, указатель ветки сдвигается на новый коммит. Предыдущие коммиты остаются неизменными. Другие ветки при этом не меняются — они продолжают указывать на свои коммиты.

### Слияние (merge)
Слияние — это объединение изменений из одной ветки в другую. Git берёт коммиты из исходной ветки и применяет их к целевой. Если изменения не конфликтуют, слияние проходит автоматически. Результатом может быть либо fast-forward (просто сдвиг указателя), либо коммит слияния (merge commit), который фиксирует факт объединения двух линий истории.
